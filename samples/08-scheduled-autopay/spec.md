# Автоплатёж по расписанию

## Новый функционал

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Автоплатёж по расписанию в мобильном банке |
| **Продукт** | Мобильный банк для физических лиц |
| **Бизнес-процесс** | Платежи физических лиц |
| **Business owner / Product owner / Аналитик** | Директор розничного бизнеса / владелец продукта «Платежи» / бизнес-аналитик команды платежей |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, сервис автоплатежей, сервис платежей, АБС, сервис уведомлений |
| **Задача в JIRA** | PAY-2311 |

### Термины

| Термин | Определение |
| :--- | :--- |
| Автоплатёж | Поручение клиента Банку регулярно выполнять платёж по сохранённому шаблону и расписанию |
| Шаблон платежа | Сохранённые реквизиты платежа: получатель (поставщик услуг или собственный счёт клиента) и лицевой счёт у поставщика |
| Дата исполнения | Календарная дата по времени Казахстана (UTC+5), в которую автоплатёж должен быть исполнен |
| Исполнение | Обработка автоплатежа в одну дату исполнения: до трёх попыток списания и платежа |
| Источник списания | Карта или текущий счёт клиента в тенге, с которых списываются деньги |

### Цели
Клиент один раз настраивает регулярный платёж — мобильная связь, интернет, коммунальные услуги, пополнение собственного депозита — и не пропускает сроки оплаты. Целевые показатели: 60 000 активных автоплатежей через 6 месяцев после запуска; доля исполнений, не выполненных по техническим причинам на стороне Банка, — не более 0,5 % за календарный месяц.

В объём задачи не входят автоплатежи с переменной суммой (на сумму выставленного поставщиком счёта): они будут описаны отдельным ТЗ.

### Архитектура решения
Мобильное приложение → сервис автоплатежей (хранение автоплатежей и расписаний) → планировщик → сервис платежей → АБС и поставщик услуг. Результат исполнения: сервис платежей → сервис автоплатежей → сервис уведомлений.

### Дизайн процесса UI
Платежи → Автоплатежи.

* Список автоплатежей: название, сумма, периодичность, следующая дата исполнения, статус; кнопка «Создать автоплатёж».
* Экран создания: шаблон платежа, сумма, периодичность, дата первого исполнения, источник списания.
* Карточка автоплатежа: кнопки «Изменить», «Приостановить» или «Возобновить», «Удалить»; история исполнений.

Макеты всех экранов, включая сообщения об ошибках, приложены к задаче PAY-2311 (версия макетов от 12.11.2026).

### Требования к изменениям

#### BPMN схема процесса
Создание автоплатежа клиентом → подтверждение → наступление даты исполнения → проверка статуса автоплатежа и источника списания → попытка исполнения → при успехе: запись в историю и push → при нехватке средств: повторные попытки → при окончательном отказе: запись в историю и push → расчёт следующей даты исполнения.

#### Функциональные требования
* **Ф-1.** Клиент создаёт автоплатёж на основе шаблона платежа. Получатель — поставщик услуг из справочника платежей Банка или собственный счёт клиента в Банке. Создание подтверждается PIN-кодом приложения или биометрией.
* **Ф-2.** Сумма автоплатежа фиксированная: целое число тенге от 100 ₸ до 500 000 ₸ включительно.
* **Ф-3.** Периодичность — еженедельно или ежемесячно. Клиент выбирает дату первого исполнения — не раньше следующего календарного дня после создания. Следующие исполнения приходятся на тот же день недели (еженедельно) или на то же число месяца (ежемесячно), что и первое.
* **Ф-4.** Если в месяце нет числа первого исполнения (29, 30 или 31), автоплатёж исполняется в последний день этого месяца. В следующих месяцах число исполнения не меняется.
* **Ф-5.** Исполнение начинается в дату исполнения в 09:00 по времени Казахстана (UTC+5). Даты исполнения не переносятся с выходных и праздничных дней: платежи поставщикам и переводы между счетами в Банке проводятся круглосуточно. Автоплатежи одного клиента с одной датой исполнения обрабатываются в порядке их создания.
* **Ф-6.** Источник списания выбирается при создании. Если в дату исполнения источник закрыт или заблокирован, попытки не выполняются: исполнение получает статус «Не исполнено» с причиной, автоплатёж переводится в статус «Приостановлен», клиенту отправляется push с причиной.
* **Ф-7.** Если на источнике недостаточно средств, выполняются ещё две попытки в тот же день — в 13:00 и в 18:00 (UTC+5). Если все три попытки неуспешны, исполнение получает статус «Не исполнено», следующая дата исполнения рассчитывается по расписанию. Частичное списание не выполняется. Если платёж отклонён по другой причине (ошибка поставщика, неверный лицевой счёт), повторные попытки не выполняются, исполнение получает статус «Не исполнено» с кодом причины.
* **Ф-8.** Клиент может изменить, приостановить, возобновить и удалить автоплатёж. Изменение суммы, источника списания или расписания, сделанное до 08:00 дня исполнения, применяется к этому исполнению, сделанное позже — к следующему. Приостановка и удаление действуют сразу: ещё не начатые попытки исполнения отменяются.
* **Ф-9.** У клиента может быть не более 20 автоплатежей в статусах «Активен» и «Приостановлен» в сумме. Ограничение защищает от ошибочного массового создания и упрощает антифрод-контроль. При попытке создать 21-й автоплатёж клиент видит сообщение «Достигнуто максимальное число автоплатежей (20)».
* **Ф-10.** По каждому исполнению клиенту отправляется push: при успехе — сумма и получатель, при статусе «Не исполнено» — причина. Push не отправляется, если клиент отключил уведомления в настройках приложения.
* **Ф-11.** В карточке автоплатежа отображается история исполнений за последние 12 месяцев: дата, сумма, статус, причина отказа.

### Sequence Diagram
Планировщик → сервис автоплатежей (08:00 UTC+5): сформировать список исполнений на дату. Сервис автоплатежей → сервис платежей (с 09:00): «Создать платёж» с идентификатором исполнения. Сервис платежей → АБС: списание с источника. Сервис платежей → поставщик услуг: платёж. Сервис платежей → сервис автоплатежей: результат попытки. Сервис автоплатежей → сервис уведомлений: push клиенту.

### Нефункциональные требования
* **НФТ-1.** Первые попытки всех исполнений текущего дня передаются в сервис платежей до 10:00 (UTC+5) при объёме до 200 000 исполнений в день.
* **НФТ-2.** Время ответа API сервиса автоплатежей на создание, изменение и просмотр — не более 800 мс для 95 % запросов при нагрузке 100 запросов в секунду.
* **НФТ-3.** Доступность сервиса автоплатежей — 99,5 % за календарный месяц без учёта плановых работ, объявленных не менее чем за 48 часов. Плановые работы не проводятся с 08:00 до 19:00 (UTC+5).
* **НФТ-4.** По одному идентификатору исполнения проводится не более одного платежа: если платёж по нему уже проведён, повторный запрос, в том числе повторная попытка, не создаёт новый платёж, а возвращает результат проведённого.

### Требования к данным
* Автоплатёж: идентификатор, идентификатор клиента, шаблон платежа, сумма в тенге (целое число), периодичность, дата первого исполнения, источник списания (идентификатор карты или счёта, без полного номера карты), статус («Активен», «Приостановлен», «Удалён»), дата и время создания и последнего изменения.
* Исполнение: идентификатор, идентификатор автоплатежа, дата исполнения, номер попытки (1–3), время попытки, статус («Исполнено», «Не исполнено»), код и текст причины отказа.
* Дата и время хранятся с часовым поясом UTC+5. История исполнений хранится 5 лет.

### Требования к интеграции
Сервис автоплатежей вызывает существующий метод сервиса платежей «Создать платёж» (дочерний документ «Сервис платежей — REST API», версия 3.4) и передаёт идентификатор исполнения как ключ идемпотентности. Новые интеграции с поставщиками не требуются.
